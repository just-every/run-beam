# Beam target acceptance

**Useful outcome:** a US employer moves its people, content and evidence from
its incumbent LMS, connects HR and workplace identity, publishes reviewed
native/package learning, enrolls role-based programs, delivers mobile and live
learning, follows up and renews it, and retrieves exact revision-bound evidence.
Agents diagnose work problems, prepare minimal interventions and measure work
outcomes under human publication, assessment and policy control.

[CONTRACT.md](CONTRACT.md) is the destination. The table preserves this repo’s
clause → person’s journey → test form and adds the current status/gap. `done`
means the narrower clause is implemented and exercised by the cited tests;
`partial`/`missing` journeys are required acceptance work, not passing tests.
Evidence paths in the Test column are repository-relative; they identify the
implemented portion only. Status is judged at the same code commit as the
contract. Public doors include /app screens/forms, /api/beam APIs, authorized
downloads, native apps, provider callbacks and rer commands; only the paid or
network edge may be faked in a test.

## Running the implemented checks

Install with `pnpm install --frozen-lockfile` (this repo has no npm lockfile).
`pnpm exec rer check --profile first-party` checks structural requirements;
the current Base contract parser additionally validates clause definitions,
status/counts and existing evidence paths. Source-lock validation uses
`node scripts/edition-authoring/cli.mjs check`; Base copies use
`node scripts/edition-authoring/cli.mjs verify-base --offline`.

`rer verify` runs the source lock/Base copy checks, build, typecheck and
public-door native/auth flows (`tests/email-link.mjs`, `tests/beam/flows.mjs`,
`tests/beam/agent-flows.mjs`, `tests/beam/regressions.mjs`). The existing
`BEAM_TEST_CHECKOUT=1 pnpm run test:journey` fresh-checkout browser journey
uses rer setup/dev/build/preview/export/import and exercises native learning
at 1440 and 390 pixels; it does not prove the new target journeys. No UI,
workflow or test is changed by this document round.

## Upgrade and recovery

Existing applied migrations keep their bytes, including import custody,
agent work, owner sign-in and resumable erasure additions. New schema work
must add migrations. A populated-installation upgrade check is owed when a
released schema changes. Restore an export with the release that made it, then
upgrade it in place, running `rer install` and `rer setup` inside that existing checkout.
BEAM-16 and OPS-002–004 define portability, erasure fencing and recovery.
